# 01 — User Journey & Workflow

> Smart Recruitment & OCR Portal — บริษัท สยามราชธานี จำกัด (มหาชน)
> หลักการ: **"AI อ่านเอกสารแทนคน → ตรวจประวัติก่อน → ค่อยลงแรงเฉพาะคนที่ผ่าน"**

## 2. User Journey — ผู้สมัคร (มือถือ)

```mermaid
journey
  title Candidate Journey (~7 นาที)
  section เริ่ม
    เปิดลิงก์/QR จาก LINE OA หรือประกาศงาน: 5: ผู้สมัคร
  section สแกนเอกสาร (AI OCR)
    ถ่ายรูปบัตรประชาชน → ชื่อ เลขบัตร วันเกิด ที่อยู่ ถูกเติมให้: 5: ผู้สมัคร
    ถ่ายรูปทะเบียนบ้าน → ที่อยู่ตามทะเบียนบ้าน ชื่อบิดา/มารดา: 5: ผู้สมัคร
    ถ่ายรูปใบขับขี่ → เลขที่/ประเภท/วันหมดอายุ: 5: ผู้สมัคร
  section ตรวจ + เพิ่มข้อมูล
    ตรวจข้อมูลที่ AI เติม (ช่องไม่มั่นใจถูกไฮไลต์เหลือง): 4: ผู้สมัคร
    กรอกเฉพาะที่เอกสารไม่มี (เบอร์, ตำแหน่ง, ประวัติงาน): 3: ผู้สมัคร
  section ยินยอม
    อ่านเอกสาร + ติ๊กยินยอมแยกฉบับ: 3: ผู้สมัคร
    เซ็น E-Signature ครั้งเดียว: 5: ผู้สมัคร
  section ติดตาม
    ได้เลขที่ใบสมัคร + ลิงก์ติดตามสถานะ: 5: ผู้สมัคร
```

## 3. Workflow — HR

```mermaid
flowchart TD
  S([ใบสมัครเข้าระบบ<br/>ข้อมูลมาจาก OCR แล้ว ไม่ต้องคีย์]) --> P[รอส่งตรวจประวัติ<br/>PENDING_CHECK]
  P --> V{HR ดูธง OCR<br/>ข้อมูลไม่ตรงเอกสาร?}
  V -- มีธงแดง --> V1[ตรวจรูปเอกสารบนจอ]
  V1 --> X
  V -- ปกติ --> X[เลือกหลายคน → Batch Export CSV<br/>ก่อน 16:00]
  X --> Q[อยู่ระหว่างตรวจประวัติ<br/>IN_CHECK]
  Q --> R{16:00 ผู้จัดการบันทึกผล}
  R -- "ไม่พบประวัติ = 0<br/>(ทั้ง Batch คลิกเดียว ยกเว้นรายที่พบ)" --> OK[ผ่าน PASSED 🔓]
  R -- พบประวัติ --> NG[ไม่ผ่าน REJECTED 🔒]
  OK --> K1[[ส่งเข้าระบบหลักอัตโนมัติ<br/>Webhook / ไฟล์ Outbox]]
  OK --> K2[Print / PDF ชุดเอกสาร<br/>พร้อมตราประทับ 'สำเนาถูกต้อง' ดิจิทัล]
  NG --> W[🟥 ห้ามคีย์เข้าสู่ระบบหลัก และห้ามพิมพ์เอกสาร<br/>API ตอบ 423 Locked]
  NG --> T[ตั้งวันลบ = วันที่ได้ผล + 30 วัน]
  T --> DEL[Retention Job: ลบไฟล์ + ลายเซ็น + ปกปิดข้อมูลส่วนบุคคล]
```

### State machine

```mermaid
stateDiagram-v2
  [*] --> PENDING_CHECK: ผู้สมัครส่งใบสมัคร
  PENDING_CHECK --> IN_CHECK: Batch Export
  IN_CHECK --> PENDING_CHECK: ยกเลิก/ส่งใหม่ (manager)
  IN_CHECK --> PASSED: ผล = 0
  IN_CHECK --> REJECTED: พบประวัติ
  state PASSED {
    [*] --> QUEUED
    QUEUED --> SENT: ระบบหลักรับแล้ว
    QUEUED --> FAILED
    FAILED --> QUEUED: กดส่งใหม่
  }
  REJECTED --> [*]: ครบ Retention → purge
```

`main_sync_status` (QUEUED/SENT/FAILED) คือสถานะย่อยของ PASSED — ผู้สมัครที่ไม่ใช่ PASSED จะเป็น `NOT_ALLOWED` เสมอ

## 5. RBAC ตาม PDPA

| การกระทำ | staff (4 คน) | manager (1 คน) |
|---|:-:|:-:|
| ดูรายชื่อ + ข้อมูลพื้นฐาน (เลขบัตรแบบ `1-1004-xxxxx-xx-8`) | ✅ | ✅ |
| ดูเลขบัตรเต็ม / ชื่อบิดามารดา / คำรับรองตนเอง (สุขภาพ, คดี) | ❌ | ✅ |
| ดูรูปเอกสาร (ยกเว้นเคส Rejected) | ✅ | ✅ |
| Batch Export ส่งตรวจ | ✅ | ✅ |
| บันทึกผลตรวจประวัติ / ดูรายละเอียดคดี | ❌ | ✅ |
| ส่งเข้าระบบหลัก (ซ้ำ) / Print PDF — เฉพาะ PASSED | ✅ | ✅ |
| Audit Log / สั่ง Retention | ❌ | ✅ |

ทุกการเปิดเอกสาร, export, print, sync, บันทึกผล ถูกเก็บลง `audit_logs`
